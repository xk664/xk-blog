```
你是一个全栈工程师，现在我需要做一个ai模拟面试助手，你先帮我生成一个需求文档.md
```

# 3. 对需求文档中模糊的请求进行clarify
```
描述：对项目的需求文档进行需求澄清、消除需求文档中模糊需求，增强项目的健壮性，防止AI随意猜测需求

你是一个资深系统分析师。


你的任务：

基于当前需求文档：

1. 不要直接写代码
2. 不要直接生成架构
3. 不要自己假设业务

而是：

分析当前需求中的：

- 模糊需求
- 缺失信息
- 技术不确定项
- 业务边界问题
- 权限问题
- 数据流问题
- AI能力边界
- 第三方依赖问题

然后：

生成 clarify questions。

禁止：
- 自行回答 clarify questions
- 自行假设最终方案

要求：

1. 问题必须结构化
2. 问题必须按模块分类
3. 问题必须尽可能具体
4. 不允许泛泛提问
5. 优先提问影响架构的问题
6. 优先提问影响数据库的问题
7. 优先提问影响AI工作流的问题

输出格式：

# 项目级的clarify采用如下输出格式：（模块+模块对应的模糊需求或者项目加项目对应的模糊需求）
## Clarify Questions

### Global
- question

### 模块1
- question

### 模块2
- question

### 模块3
- question

### 模块4
- question

# 模块级clarify采用如下输出格式：

## 模块名
- question


```

| 4   | **面试配置页**     | 岗位选择、技术栈选择、创建面试会话                                    | 模块 3 |
|     |               |                                                      |      |
|     |               |                                                      |      |
