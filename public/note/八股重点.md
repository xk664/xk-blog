# 计网

- 三次握手
- 四次挥手
- 浏览器输入一次URL后，按回车的流程
1.URL解析如果输入的协议或者主机名不合法，直接交给存储引擎查找相应的内容，合法就下一步
2.域名解析，先查找浏览器是否有缓存，有就返回，没有就DNS
3.每个主机都有根服务器的地址，先去问根服务器的这个域名的顶级域名的服务器在哪里，逐渐往下问，知道找到ip,
4.MAC地址，通过子网掩码（与运算）判断这个IP是否和主机在同一个网络下，在的话就直接ARP协议获取MAC地址，不在就获取路由器MAC地址，转发给路由器
5.建立TCP连接，四次握手
6.如果是HTTPS协议，还要建立TLS连接
7.然后就可以请求
8.服务器响应数据

- select poll epoll
select:当调用select的时候，首先内核会将所有fd(文件描述符)拷贝到内核（临时的），然后内核再**轮询**然后再将有数据的fd返回给用户，而且每次调用select都要拷贝，而且fd限制为1024，数据结构为bitmap

poll:再select的基础上没有1024的限制，数据结构：数组

epoll: 当调用epoll的时候，会先将用户传来的fd拷贝到红黑树（便于修改，增加，删除fd）,然后每个fd都绑定了walk_up()回调函数，当某一个fd有数据，就会直接调用回调函数，将其fd放入就绪队列，然后后面直接将就绪队列的fd返回就行，下一次调用epoll,也只需要直接拷贝就绪队列的内容即可

## AIO

AIO就是不用用户线程去内核拷贝结果，CPU直接将拷贝到用户缓冲区

## Binlog和redo log的区别

- binlog有三种记录方式（记录SQL,记录将哪一行从什么修改成什么，混合）而redolog是将那一页的哪个偏移量的数据从什么改成什么，由于不同的存储引擎对应的就够，不一样，所以redo log属于存储引擎层
- binlog属于server层，redo log属于存储引擎层(innodb独有)
- binlog主要用于主从数据库的同步，redolog用于自己的实例化
